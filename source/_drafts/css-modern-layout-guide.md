> 本篇目标：读完能对任意一张设计稿快速判断该用哪种布局方案，并讲清每种方案的适用边界。写作时每个结论都配最小 demo 验证。

## 一、为什么布局方案值得复盘一遍

- 从 float + clearfix → Flex → Grid → 容器查询，每一步解决了什么痛点
- 现状：很多项目停留在「Flex 一把梭」，Grid 用得少的原因分析

## 二、Flex：一维内容布局

- 主轴/交叉轴模型，常见误区（`flex: 1` 的三值展开）
- 典型场景：导航栏、工具条、居中、等分
- 什么时候 Flex 开始变别扭（二维对齐时）

## 三、Grid：二维结构布局

- 网格线、区域命名（`grid-template-areas` 的可读性优势）
- `auto-fill` + `minmax` 实现免媒体查询的响应式卡片列表
- 典型场景：后台布局、不规则瀑布流、海报式排版

## 四、容器查询：组件级响应式

- 与媒体查询的本质区别：响应「父容器」而不是「视口」
- 可复用组件在容器查询下的写法（`@container` + `container-type`）
- 兼容性现状与降级策略

## 五、选型决策图

- 一张流程图收束：一维 → Flex；二维 → Grid；组件内部自适应 → 容器查询
- 表格对比：语义、浏览器支持、坑点

## 六、总结

- 一句话记住：**Flex 管内容怎么排，Grid 管页面怎么分，容器查询管组件长在哪**
