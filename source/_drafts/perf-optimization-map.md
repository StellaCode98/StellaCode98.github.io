> 本篇目标：作为性能优化分类的开篇，建立体系框架；后续每篇优化文章都挂在这张图的某个格子上。强烈建议配自己项目的真实数据。

## 一、先定义「快」：指标体系

- 用户体验视角：LCP / INP / CLS（Core Web Vitals 演进，FID 为什么被 INP 取代）
- 工程视角：TTFB / FCP / TTI，各自归因到哪一层（网络 / 渲染 / 脚本）
- 配图：指标与用户感受的对应关系

## 二、优化手段分层地图

- **网络层**：HTTP 缓存策略、CDN、资源预加载（preload/prefetch/preconnect）、HTTP2/3
- **资源层**：代码分割、Tree Shaking、图片格式（webp/avif）、按需加载
- **渲染层**：关键渲染路径、防抖节流、虚拟列表、避免长任务（切片 / scheduler）
- **构建层**：产物分析、压缩、scope hoisting
- 每层一张「问题信号 → 排查工具 → 手段」对照表

## 三、怎么定位：工具链

- Lighthouse / WebPageTest / Performance 面板的分工
- 火焰图怎么读：定位长任务与布局抖动（配截图）

## 四、闭环：前端监控体系

- 采集：web-vitals 库 + PerformanceObserver
- 上报：sendBeacon、采样率、错误兜底
- 看板与告警：定基线 → 看趋势 → 版本对比
- 这部分展开成独立一篇「从 0 搭建前端监控」

## 五、实战案例（占位）

- 用自己项目跑一次完整流程：测指标 → 定位 → 优化 → 复测，贴数据

## 六、总结

- 一句话记住：**没有度量就没有优化；优化只对指标负责**
